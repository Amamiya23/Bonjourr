# Bonjourr 云端架构

同一份前端分别构建为网页版和浏览器插件。Worker 托管网页版及 `/api/`，D1 保存共享设置、链接、设备授权和修改历史，R2
保存按内容摘要命名的媒体分块。WebDAV 仅用于旧备份导入和独立历史备份，不再运行客户端 WebDAV 自动同步。

## 使用与迁移

1. 网页版直接显示登录页。插件重新加载 `release/chrome` 后，在“设置管理 → 同步类型 → Bonjourr 云端”登录。
2. 所有设备使用同一用户名和密码。云端已有内容时，首次登录自动下载；同一账号重新登录会保留本机未同步修改。
3. 云端为空时，在内容完整的设备上通过“导入与恢复 → 上传本机内容”初始化。旧备份可先在“备份 → 本机备份”中恢复。
4. 在“设备”中查看和撤销登录会话。登录有效期为 30 天；修改密码会撤销其他会话，当前浏览器自动换用新令牌。
5. 第一个账号成为管理员，之后默认关闭注册。管理员在“管理 →
   允许注册”中开关注册。其他账号各自拥有独立设置、链接、媒体和备份。

从配对版升级时，原数据迁移到首个管理员账号。已有内容或管理设备的实例不会让匿名访客抢先领取管理员：可用原管理设备创建账号，或执行
`deno task cloud:account`，使用本地恢复密钥建立初始管理员。初始用户名、随机密码保存在被 Git 忽略的
`.cloud/initial-admin.txt`，登录后可自行修改。旧配对接口返回 410，旧设备需要改用账号登录。

已登录设备可在离线时使用本机缓存。关闭页面后客户端不在后台持续同步；定期备份由 Worker Cron
执行。切换账号会清理前一个账号的页面缓存，其他标签页会重新验证登录。

## 同步协议

- 设置按字段保存；链接和文件夹按稳定 `_id` 保存；数组作为一个字段处理。
- 每项记录独立版本号和删除标记。客户端保存上次确认的基线，发送 `{key, json, deleted, baseRevision}`
  修改列表，不发送整份数据来覆盖服务端。
- Worker 用 D1
  单个事务检查全部版本、提交修改并写历史。不同条目的离线修改自动合并；同一条目并发修改暂停，界面显示两端内容，逐项选择。
- 请求带持久化的唯一编号。超时后重放同一请求，不重复修改；成功确认前本机仍保留待发请求。下载期间发生本机编辑时取消应用，保留用户操作。
- 删除保留墓碑，离线旧设备不会仅因重新连接而复活数据。清空全部快捷链接需要另外确认。删除分组或文件夹后，仍有其他设备新增的子项时，服务端拒绝产生孤立链接。
- `about`、本机布局、当前分组、书签同步绑定和运行时缓存不进入共享数据。天气自定义 API 配置、链接、文件夹和背景配置共享。
- 媒体按 8 MiB 分块、SHA-256
  校验、去重上传。完整资源发布前先确认全部分块已存在；下载先暂存并校验，随后才应用设置。历史版本引用的资源不会立即回收。

## 授权与凭据

账号密码采用带独立随机盐的 PBKDF2-SHA-256，100,000 次迭代；设备令牌在 D1 中只保存 SHA-256
摘要。密码不会写入页面缓存或云端备份。登录和注册按 IP、用户名限制尝试次数；注册开关和首任管理员分配在事务内检查。

所有个人 API 都从登录会话取得账号，客户端不能自行指定账号。D1 的记录、历史、幂等请求和备份均按账号过滤；R2
新账号媒体保存到独立前缀。原数据与媒体保留给首任管理员。普通账号不能改变注册设置。

静态文件仍公开，未登录的网页版只显示登录入口。个人数据和媒体要求有效登录令牌。API 禁止缓存，PWA
不拦截认证或数据接口。每个域名分别保存会话，换域名输入同一账号密码即可，无需配对码。

恢复密钥和备份加密密钥通过 Wrangler secrets 部署，绝不进入静态构建或版本库。WebDAV 凭据用 AES-GCM
加密保存，配置接口不返回密码。请保管 `.cloud/owner-key` 和 `.cloud/backup-key`。

## WebDAV 历史备份

“备份”是独立于同步类型的设置，包含“云端备份”和“本机备份”。登录后在“云端备份”中保存自己的 WebDAV 配置，每 6
小时生成一份独立的时间戳快照，也可手动触发。“本机备份”提供手动备份及旧数据导入，不改变当前同步方式。旧版 WebDAV
同步类型自动迁移为关闭，地址和凭据保留。

媒体分块先上传，快照最后发布；失败不会将任务标为完成。快照包含共享状态和媒体引用，不包含设备令牌、管理密钥或 WebDAV
认证密码。

恢复时先下载并校验缺失媒体，再按当前版本号原子替换共享数据并记录历史。设备有离线修改时仍走正常冲突流程。当前不会自动清理历史或媒体，避免将仍被备份引用的内容移除；存储占用需由实例所有者监控。

## 开发与部署

如果 D1 数据或整个实例丢失，可以在新实例重新设置 WebDAV 配置，然后在“恢复指定备份文件”中输入 WebDAV
中的历史快照文件名。恢复流程不依赖原 D1 中的备份列表，也会补回缺失的 R2 媒体。

开发和前端构建使用 Deno，部署工具使用已获准的 Node.js/Wrangler，不增加应用依赖。

```powershell
deno task cloud:build
deno task cloud:types
deno task cloud:dev
deno task cloud:migrate
deno task cloud:deploy
```

本地开发前，将 `.dev.vars.example` 复制为 `.dev.vars`。首次生产部署用 `deno task cloud:secrets` 生成密钥，再执行
`deno task cloud:deploy --secrets-file .cloud/secrets.json`，将代码与密钥一次部署。该目录被 Git
忽略，不会打包进静态页面。新克隆的项目需要先执行 `deno task cloud:types` 生成绑定类型，CI 也会先执行这一步。

初次部署需要独立的 D1 和 R2 绑定，修改 `wrangler.jsonc` 中的数据库 ID、桶名和允许来源，并修改
`src/scripts/shared/cloud.ts` 的默认服务端地址。`.dev.vars` 仅用于本地测试，生产使用 `OWNER_KEY`、`BACKUP_KEY` 两个
secrets。生产密钥必须来自密码学安全随机数，备份密钥为 32 字节的十六进制文本。

本地 API 回归测试：应用本地迁移，准备带旧设备和 `sync/favicon = "legacy"` 的本地迁移样本，再运行 `cloud:dev`。设置
`BONJOURR_CLOUD_TEST_URL=http://localhost:8787` 后执行
`deno task test --allow-net tests/cloud/worker.test.ts`。测试只允许
localhost/127.0.0.1，覆盖管理员竞争、账号隔离、注册开关、限流、会话撤销以及同步冲突，不向生产写测试数据。

当前以 Worker 为主部署。若同时保留旧 Pages
项目，也应更新其客户端。原地址可用于迁移本机数据，直接重定向后无法读取旧来源的 localStorage。
